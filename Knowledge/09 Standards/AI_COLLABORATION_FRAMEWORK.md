## 1. Purpose

This framework defines how AI assistants (Hermes, Claude, Codex, etc.) are used in Guardian development. It ensures:
- **Traceability** of AI-generated content
- **Quality gates** for AI output
- **Human accountability** for all merged code
- **Knowledge capture** of AI-assisted decisions

---

## 2. AI Roles & Permissions

| Role | Permissions | Restrictions |
|------|-------------|--------------|
| **Research Assistant** | Literature search, summarization, spike prototypes | No production code; no commits |
| **Code Generator** | Scaffolding, boilerplate, test stubs, migrations | No business logic; human review mandatory |
| **Documentation Assistant** | Drafting, formatting, cross-referencing, sync | No architectural decisions; human approval |
| **Reviewer** | Static analysis, pattern detection, suggestion | No approval authority; advisory only |
| **Architect (Human)** | All decisions, ADRs, approvals | — |

## 3. AI Usage Workflow

### 3.1 Development Flow with AI
```
Human: Define requirement → Create feature spec ([[TEMPLATE_FEATURE]])
       │
       ├─► AI: Research spike → [[RESEARCH_<topic>.md]]
       │
       ├─► AI: Generate scaffold → Module structure + tests
       │
       ├─► Human: Implement business logic
       │
       ├─► AI: Generate test cases → Edge cases, fixtures
       │
       ├─► AI: Draft documentation → Module docs, API ref
       │
       └─► Human: Review, refine, approve → PR
```

### 3.2 Mandatory Human Gates
| Gate | Human Action |
|------|--------------|
| **Architecture Decision** | Create/approve ADR |
| **Public API Design** | Approve function signatures, types |
| **Security Policy** | Approve risk tier, checkpoint requirements |
| **Code Merge** | Human reviewer + CI pass |
| **Release** | Release Manager signs off |

```powershell
# 3. Policy gate (if mutation)
```

## 6. Quality Assurance for AI Output

### 6.1 Automated Checks
| Check | Tool | Applied To |
|-------|------|------------|
| Syntax | `Import-Module` | All AI code |
| Style | PSScriptAnalyzer | All AI code |
| Tests | Pester (generated + human) | All AI code |
| Architecture | `Test-GuardianArchitectureDrift` | Structural changes |
| Policy | `Test-GuardianPolicy` | Mutations |
| Contracts | JSON Schema | Bridge messages |

### 6.2 Human Review Checklist for AI Code
- [ ] Policy gate present on mutations
- [ ] Checkpoint before state change
- [ ] Audit write on success/failure
- [ ] Error handling with rollback
- [ ] No hardcoded paths (uses `$GuardianEnv`)
- [ ] Typed contracts (not raw hashtables)
- [ ] Tests cover generated logic
- [ ] Documentation matches implementation

## 8. Security & Compliance

### 8.1 Data Handling
| Data Type | AI Access | Retention |
|-----------|-----------|-----------|
| Source code | Yes (context) | Session only |
| Config (no secrets) | Yes | Session only |
| Secrets | **Never** | N/A |
| Audit logs | Summarized only | Session only |
| User data | **Never** | N/A |

### 8.2 Prohibited AI Actions
- ❌ Write/modify secrets
- ❌ Execute mutations without human approval
- ❌ Approve PRs or merges
- ❌ Create ADRs without human sponsor
- ❌ Access production systems
- ❌ Train on proprietary code

## 10. Incident Response

### 10.1 AI-Related Incidents
| Incident Type | Response |
|---------------|----------|
| AI-generated bug in production | Standard incident + add AI context to postmortem |
| AI hallucination in docs | Revert + add verification gate |
| AI security suggestion missed | Review prompt/guardrails; update checklist |
| AI architectural suggestion causes drift | ADR to document decision; update baseline |

